# agent-era Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude Code plugin whose `/agent-era` skill runs a local Node script against the user's authenticated `gh` CLI and produces a 1200×630 before/after-AI-agents share card (PNG, SVG fallback) plus a terminal summary.

**Architecture:** Small, pure-function modules (month math, era detection, stats, SVG card, summary text) around a thin `gh` adapter that is injected everywhere, so all logic is unit-tested with fakes. `bin/agent-era.js` orchestrates: fetch → compute → render → print. The plugin's skill only runs the script and relays its output.

**Tech Stack:** Node ≥ 22 (ESM, standard library only, `node:test`), `gh` CLI ≥ 2.x, headless Chrome/Chromium for PNG, Biome 2.x (dev only) for lint/format.

**Spec:** `docs/superpowers/specs/2026-10-23-agent-era-design.md`

## Global Constraints

- No runtime dependencies. `package.json` has only `devDependencies` (`@biomejs/biome`). No `npm install` is needed to run the tool.
- Only network calls: GitHub API via the `gh` binary. Nothing else is written except the output files.
- The card and the summary never contain repo or org names. (The org-access caveat names orgs. It is printed only in the terminal, never on the card.)
- Card: 1200×630. Gradient `#1b1340` → `#3a1d6e` (55%) → `#e2557a`, diagonal. White text. Top-left label `@<login> · pull requests`. Headline `<N.N>×`, with "more PRs per month with AI agents" under it. Before/after PRs/month on the right, with the before number at 55% opacity and the labels "before" / "after". Monthly bars along the bottom: pre-era bars `rgba(255,255,255,.35)`, era bars `#fff`, rounded tops.
- Fonts: system stack only, `-apple-system, "Segoe UI", Helvetica, Arial, sans-serif`. No network fonts.
- Era detection: candidate months from `2023-01`, full months only, ratio = mean(m..m+2) / mean(12 months before m) ≥ 2. Pick the max ratio. Fallback `2025-02`. Override `--since YYYY-MM`.
- Before = mean PRs/month over the 12 full months before the era start, or over the months from the first-activity month if that is later. After = mean over full months from the era start through last month. Multiplier = after/before, rounded to 1 decimal. `null` when before is 0.
- Commits: REST `search/commits` with `author:<login> committer-date:<range>`, `total_count` only. Yearly totals for the whole history, plus monthly totals for the last 36 months, plus any older months the before window needs. All text that mentions commits says "commits on default branches".
- Lines: median of (additions + deletions) per **merged** PR, from a sample of ≤ 500 PRs per window. Never totals.
- Output file: `agent-era-<login>.png` in the cwd unless `--out <path>` is given. With no Chrome, write `agent-era-<login>.svg`.
- Lint/format with Biome. `npm run check` must pass before every commit.

## Review Focus

1. **`gh` missing or logged out:** print one clear line (`gh is not installed` / `run: gh auth login`), exit 1, write no files. *(Test in Task 2.)*
2. **Zero PRs ever:** print "No pull requests found for @login.", exit 0, no card. *(Test in Task 7.)*
3. **First PR at or after the era start (brand-new user):** before = 0, multiplier `null`. The card shows only the after rate, with no "×" headline, and does not crash. *(Tests in Tasks 3 and 5.)*
4. **Secondary rate limit that won't clear during the commits or lines fetch:** the run still produces the PR card. The failed section is omitted, and a caveat says why. *(Test in Task 7.)*
5. **Run on the 1st of a month:** the current partial month is never used in detection, before, after or bars, so a 1-day month can't create a fake drop or jump. *(Test in Task 3.)*

### Task 2: gh adapter

**Files:**
- Create: `src/gh.js`, `test/gh.test.js`

**Interfaces:**
- Produces:
  - `class GhError extends Error { code: 'not_installed' | 'not_authenticated' | 'rate_limited' | 'failed' }`
  - `createGh({ exec?, sleep?, maxRetries? = 3, retryDelayMs? = 60000 }) → { graphql(query: string): Promise<object>, rest(path: string, params?: Record<string,string>): Promise<object>, login(): Promise<string>, createdAt(): Promise<string> }`
  - `exec(args: string[]) → Promise<{ stdout: string, stderr: string, code: number }>`. The default uses `node:child_process` `execFile('gh', args)`. `ENOENT` → `GhError('not_installed')`.
  - `graphql` runs `gh api graphql -f query=<q>` and returns parsed `.data`. `rest` runs `gh api -X GET <path> -f k=v…` and returns the parsed JSON.
  - `login()` / `createdAt()` read `gh api user` (`.login`, `.created_at`), cached after the first call.
- Rate limits: stderr matching `/secondary rate limit|rate limit exceeded|HTTP 429/i` → `await sleep(retryDelayMs)` and retry, up to `maxRetries`. Then throw `GhError('rate_limited')`. Stderr matching `/auth login|not logged in|HTTP 401/i` → `GhError('not_authenticated')`.

  - `retries secondary rate limit then succeeds`: the first call has stderr `"You have exceeded a secondary rate limit"` (code 1), and the second succeeds. Assert 2 exec calls and 1 sleep call.
  - `gives up after maxRetries`: always rate-limited, so it rejects with `code === 'rate_limited'` after `maxRetries + 1` calls.
  - `not installed`: the fake throws `{ code: 'ENOENT' }`, so it rejects with `code === 'not_installed'`.
  - `not authenticated`: stderr `"To get started with GitHub CLI, please run:  gh auth login"`, so `code === 'not_authenticated'`.

### Task 3: Era detection and before/after stats

**Files:**
- Create: `src/era.js`, `test/era.test.js`, `test/fixtures/caleb-monthly.js`

**Interfaces:**
- Consumes: `addMonths`, `monthRange`, `lastFullMonth` from Task 1.
- Produces (`monthly` is `Record<"YYYY-MM", number>`, and missing months count as 0):
  - `detectEraStart(monthly, now: Date): { month: string, source: 'detected' | 'default' }`
  - `beforeAfter(monthly, eraStart: string, now: Date): { before: number, after: number, multiplier: number | null, beforeMonths: number, afterMonths: number, shortHistory: boolean }`. `before` and `after` are unrounded means, and `multiplier` is rounded to 1 decimal.
  - `firstActiveMonth(monthly): string | null`
- Detection rules (algorithm not implied by the signature):
  - Candidates: m ∈ [`max('2023-01', first active month)`, lastFull − 2].
  - Prior window: the 12 months before m, clipped to start no earlier than the first active month. Skip m if the prior sum is 0.
  - Ratio = mean(m, m+1, m+2) / mean(prior). Pick the highest ratio ≥ 2; ties go to the earliest month. If none qualifies, return `{ month: '2025-02', source: 'default' }`.
- `shortHistory` is true when the first active month is later than eraStart − 12.

**Interfaces:**
- Consumes: the `createGh` result (`gh`) from Task 2, and the month utils.
- Produces:
  - `fetchPrMonthly(gh, login: string, createdAt: string, now: Date): Promise<{ monthly: Record<string,number>, yearly: Record<string,number> }>`. Step 1 is one GraphQL query with an alias per year (`y2008 … y<current>`) doing `search(type: ISSUE, query: "author:<login> is:pr created:<Y>-01-01..<Y>-12-31") { issueCount }`. Step 2: for each year with a count > 0, the months of that year (through the current month), batched as **24 aliases per query** (`m2025_01`), each with `created:<YYYY-MM-01>..<monthEnd>`.

Each count is one REST call, `search/commits` with `q=author:<login> committer-date:<start>..<end>`, reading `.total_count`, with `await sleep(paceMs)` between calls.
  - `fetchLineSample(gh, login, months: string[], cap = 500): Promise<number[]>`. Pick evenly spaced months from `months`, and for each run one GraphQL `search(type: ISSUE, first: 100, query: "author:<login> is:pr is:merged created:<range>") { nodes { ... on PullRequest { additions deletions } } }`. Collect `additions + deletions` until `cap` is reached or the months run out.

  - `findRestrictedOrgs(gh): Promise<string[]>`. For each org in `gh api user/orgs`, call `rest('orgs/<org>/repos', { per_page: '1' })`. Return the orgs where that call throws `GhError` with stderr containing `SAML` or `SSO` or `HTTP 403`. Other errors are ignored.

### Task 7: CLI orchestration

**Files:**
- Create: `bin/agent-era.js`, `src/run.js`, `test/run.test.js`

**Interfaces:**
- Consumes: everything above.
- Produces:
  - `run({ argv: string[], gh, now: Date, sleep, render, log: (msg) => void, progress: (msg) => void }): Promise<{ exitCode: number, outputPath: string | null, stats: CardStats | null }>`
  - `bin/agent-era.js` wires up the real `createGh()`, `new Date()`, `setTimeout` sleep, `renderPng`/`findChrome`, `console.log` for the summary and `process.stderr` for progress, then `process.exit(exitCode)`.
- Args: `--since YYYY-MM` (validated: the format, and it must be before `lastFullMonth`; otherwise exit 2 with a message), `--out <path>`, `--no-commits`, `--no-lines`, `--help`.
- Flow:
  1. login/createdAt
  2. `fetchPrMonthly`
  3. Zero PRs → log "No pull requests found for @<login>.", exit 0.
  4. Era (flag or detect), then `beforeAfter`.
  5. Commits: needed months = union(last 36 full months, eraStart − 12 … last full month). Years = createdAt year … current year.
  6. Lines: before window and after window (after capped to the last 12 full months).
  7. `findRestrictedOrgs`.
  8. Render: PNG if Chrome is found, otherwise write the `.svg` and add the caveat "Chrome not found — wrote SVG; open it in a browser and screenshot, or set CHROME_PATH."
  9. `log(formatSummary(...))`.
- Steps 5–7 each sit in their own try/catch. If one throws `GhError('rate_limited')` or any other error, that section is `null` and a caveat says why. PRs (step 2) failing is fatal: exit 1 with the message.
- `GhError` `not_installed` → "agent-era needs the GitHub CLI: https://cli.github.com". `not_authenticated` → "Run `gh auth login` first." Both exit 1 and write no files.
- Progress lines go to stderr, e.g. `Counting PRs… (2/9)` and `Counting commits… (12/54)`.
